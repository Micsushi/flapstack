Orca is MIT licensed. Flapstack is Apache-2.0. Substantial copied code must keep
the Orca MIT copyright and license notice, and every imported dependency must
pass Flapstack's package, native-runtime, and release audits.

## Mobile source status

The Orca mobile app is already in the same repository under `mobile/`. It is a
real Expo/React Native application, not a placeholder or separate repository:

- 1,476 tracked files under `mobile/`.
- Expo 55, React Native 0.83, Expo Router, secure storage, notifications,
  camera pairing, WebSocket transport, xterm/WebView terminal, and native audio.
- iOS and Android configuration lives in `mobile/app.json`; native projects are

  required.
- Routes cover pairing, hosts, workspaces, accounts, agent history, terminal,
  files, editing, source control, pull requests, diff review, tasks, browser,
  notifications, troubleshooting, and settings.

No separate mobile clone is needed. Before any reuse, fast-forward the Orca fork
or create a fresh worktree at the inspected upstream commit. The latest upstream
contains additional mobile diff, terminal, and host-connection fixes not present
in the checked-out fork.

## Improvements to existing Flapstack features

### Provider accounts and subscriptions

Keep Flapstack's onboarding, encrypted credential service, usage database,
alerts, budgets, organization usage, and run attribution. Add Orca's stronger
runtime isolation:

1. Give every managed Codex account its own `CODEX_HOME` and every managed
   Claude account its own complete credential store.
2. Snapshot provider account ID and credential mode on each run. Existing
   processes keep their original account after a switch.
3. Keep secrets in the main process. Remove renderer-callable RPCs that return
   plaintext Claude OAuth tokens.
4. Capture and atomically persist rotated Claude refresh tokens. Flapstack's
   current `refreshClaudeToken` helper is not connected to managed accounts.
5. Resolve usage from the selected account home/credential, not only global
   `~/.codex` and `~/.claude`.
6. Show every account's last known quota and active state on desktop and mobile.
7. Preserve API-key and custom-provider modes. Account isolation must support
   both subscription OAuth and usage-based API credentials.

Do not copy Orca's Codex reset-credit action until an official, stable OpenAI
contract is available. Treat provider-internal endpoints as replaceable probes,
not durable product APIs.

### Terminal

Reuse Flapstack's terminal router, output batching, window/pane model, and four
visible-Chat limit. Add Orca's daemon-owned PTY lifetime, xterm serialized state,
configurable retained rows, backpressure, cold parking, and restart reattachment.
Nested terminal splits may be unbounded by the Chat-group cap only while resource
budgets remain enforced.

### Quick Open

Replace false-empty error handling with typed failures. Use streamed `rg`,
cancellation, a shared single-flight workspace scan, ranked result types, and
keyboard-first navigation. Do not add a second file index until profiling proves
the existing filesystem search cannot meet the budget.

### Diff review

Store comments as file, side, line/range, body, scope, diff identity, and sent
time. Re-anchor or mark stale when the diff changes. Sending feedback creates a
normal user-visible agent turn and never mutates Git by itself.

### File workspace

Extend the existing file router and Monaco/Markdown surfaces. Writes use
compare-and-save with content identity, external-change detection, explicit
conflict resolution, undo, and existing permission/audit rules. Avoid copying
Orca's renderer store or metadata model.

### Mobile

Keep Flapstack's stronger default-off LAN bridge, device keys, authority grants,
step-up approval, revocation, and stale read-only behavior. Adapt Orca's Expo
screen structure, secure-store transport, terminal WebView, protocol gate,
offline caches, source-control screens, and device build workflow. Do not copy
Orca's RPC protocol wholesale; the native app must consume Flapstack's typed
mobile-control contracts.

### Agent runtimes and CLI

Keep structured Codex, Claude, Cursor, OpenCode, and local-model adapters as the
preferred path. A generic TUI runtime is an explicit lower-fidelity fallback
with terminal-only status, permissions, resume, usage, and tool limitations.
The new CLI stays a thin client over current tRPC/product services rather than
becoming another state authority.

## Subscription and API verdict

Official provider behavior is clear:

- OpenAI Codex supports [ChatGPT sign-in for subscription access and API-key
  sign-in for usage-based access](https://learn.chatgpt.com/docs/auth).
- Claude Code supports Pro, Max, Team, Enterprise, and Console accounts; an
  `ANTHROPIC_API_KEY` selects key-based access. The free Claude.ai plan does not
  include Claude Code. See [Claude Code authentication setup](https://code.claude.com/docs/en/getting-started#authenticate).

Both Orca and Flapstack work with OpenAI and Anthropic subscriptions as well as
API credentials. They launch the real provider runtimes and reuse their auth
formats rather than converting subscriptions into API keys.

| Area                                | Flapstack                                                             | Orca                                                                      | Better base         |
| ----------------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------- | ------------------- |
| Subscription and API-key onboarding | Explicit provider and billing choices                                 | Uses system default plus managed account flows                            | Flapstack UX        |
| Codex multi-account isolation       | Missing                                                               | Per-account homes, host/WSL targeting, hot-swap                           | Orca                |
| Claude multi-account list/switch    | Present                                                               | Present, with isolated full credentials                                   | Orca implementation |
| Claude token refresh                | Managed accounts retain access tokens; refresh helper is disconnected | Full credential blob, proactive refresh, atomic rotated-token persistence | Orca                |
| Secret boundary                     | OS-encrypted storage, but token-returning renderer RPCs remain        | Runtime auth stays behind main-process account services                   | Orca boundary       |
| Active account usage                | Global CLI credentials can disagree with selected managed account     | Per-account usage and inactive-account previews                           | Orca                |
| Historical/scoped usage             | SQLite history, alerts, budgets, attribution, organization APIs       | Strong live quota roster and account switcher                             | Flapstack           |
| Remote and WSL account scope        | Missing                                                               | Runtime/host/distro scoped                                                | Orca                |

The target is a hybrid: Orca-style isolated auth homes and token lifecycle feeding
Flapstack's existing usage, budget, audit, and run-snapshot systems.

## Delivery order

### S7: Daily workspace control

Ship provider account isolation first, then Quick Open, diff comments, editable
files/previews, durable terminal sessions, and one integrated gate. This stage
improves daily work without introducing remote execution.

### S8: Connected development workflows

Add forge/task providers, embedded browser and Design Mode, the operator CLI,
generic TUI agents, and controlled Computer Use. Every entry point reuses
Flapstack authority, permissions, audit, undo, and run services.

### S9: Remote and native reach

Add the versioned execution-host protocol and headless service before SSH and
native mobile. Then add WSL parity, the Expo app, mixed-version recovery,
device builds, owned ephemeral VM runtimes, and remote/mobile/VM integrated
acceptance.

### S10: Sharing, distribution, and support

Add versioned skill bundles and artifact links, localization, signed updater
channels with rollback, and redacted crash/support workflows. Hosted services
remain optional and replaceable; local Flapstack operation cannot depend on
them.

## Porting rules

1. Reimplement against Flapstack interfaces by default; copy a focused Orca
   module only when it is smaller and safer than adapting the behavior.
2. Never transplant Orca's global stores, metadata model, RPC protocol, daemon,
   or mobile backend as a unit.
3. Preserve the four-visible-Chat product decision. Orca's infinite terminal
   splits are a terminal behavior, not permission to create unlimited live Chat
   surfaces.
4. Keep all destructive Git, filesystem, remote-host, and computer-use actions
   behind existing permission, preview, audit, and reversal contracts.
5. Bind every copied behavior to focused tests plus Flapstack's affected
   production path and package gate.
